# Shadow Coach

> Things I’ve shipped：ShadowCoach

ShadowCoach 是一款 AI 简历优化工具。用户上传简历并输入目标岗位 JD 后，系统会分析岗位要求与候选人经历，识别信息缺口，必要时主动追问，再生成针对岗位优化的简历。

我通过这个项目跑通了从需求调研、产品设计、Agent 架构迭代，到登录、支付和部署的完整 Vibe Coding 流程。

---

## 1. WHY：为什么做这个项目

### 需求背景

使用 ChatGPT、DeepSeek 等通用模型优化简历很方便，但实际效果并不稳定：

- 模型容易停留在关键词匹配，没有理解岗位真正关注的能力；
- 为了迎合 JD，可能添加用户没有提供的经历或成果；
- 多轮修改时，局部要求可能导致整份简历发生变化。

简历不仅需要写得专业，更需要保证真实。因此，我为 ShadowCoach 确定了一个基本原则：

> AI 不替用户创造经历，只帮助用户更好地表达真实经历。

当材料足够时，系统可以直接优化；当关键证据不足时，系统应该先向用户提问，而不是继续生成。

### 竞品调研

国内相关产品主要集中在简历模板、ATS 评分、JD 匹配和一键改写。这些产品提高了简历制作效率，但较少处理“信息不足时怎么办”。

ShadowCoach 因此选择了三个切入点：

1. 识别简历与 JD 之间的证据缺口；
2. 信息不足时主动追问；
3. 生成后检查事实和修改范围。

除了验证产品需求，我也希望通过这个项目完成一次从想法到上线的 Vibe Coding 实践：

```text
需求调研 → 产品原型 → AI 工作流
→ 全栈开发 → 测试迭代 → 支付与部署
```

## 2. HOW：产品方案与架构演进

### 产品流程

ShadowCoach 的基本使用流程是：

```text
上传简历与 JD
→ 分析岗位和候选人经历
→ 判断是否需要补充信息
→ 追问或生成优化稿
→ 查看修改原因
→ 继续局部优化
→ 导出简历
```

与一键改写不同，ShadowCoach 会在生成前判断信息是否充分，并在生成后检查内容是否可信。

### 从单 Prompt 到多阶段 Pipeline

第一版只实现了“简历 + JD → 优化稿”的基本链路。模型需要在一次调用中完成岗位理解、事实抽取、内容规划和简历改写，输出容易出现结构漂移和事实越界。

继续增加 Prompt 规则只能解决局部问题。因此，我将流程拆分为：

```text
岗位理解 → 事实抽取 → 证据排序
→ 叙事规划 → 简历改写 → 质量检查
```

每个阶段只负责一类任务，使输出更稳定，也更容易定位问题。

模型调用最初通过 Dify 完成，之后迁移到 Node.js 后端直连，以便统一管理超时、重试、模型参数和阶段日志。模型层采用兼容接口，目前支持 DeepSeek 和 Kimi 切换。

### 从固定流程到受控 Agent Loop

多阶段 Pipeline 仍然是一条固定路径。即使简历缺少关键证据，系统也会继续生成。

为解决这个问题，我引入 Agent Planner，让模型根据当前信息提出下一步行动，例如继续分析、询问用户或开始改写。

同时，使用 Harness 管理 Agent 的运行过程：

```text
Harness 准备上下文
→ Planner 提出下一步行动
→ Harness 校验并执行
→ 更新状态
→ 继续、追问或结束
```

其中，Planner 负责提出行动，Harness 负责管理上下文、状态、执行边界和停止条件，Workflow 负责完成事实抽取、简历改写等具体任务。

这是一套受控的 Agent Loop，而不是让模型自由调用工具。

### 证据补充与质量检查

当关键证据不足时，系统会先向用户提问。用户补充的内容会进入 Evidence Store，成为后续改写可以使用的事实。

系统会区分三类信息：

- 原始简历中的事实；
- 用户后续补充的事实；
- JD 对候选人的要求。

只有前两类信息可以写入简历，JD 只用于确定表达重点。

生成完成后，Verifier 会检查是否修改了公司、职位和日期，是否添加了未经确认的经历，以及局部修改是否影响其他内容。检查不通过时，系统会针对问题返修一次。

### 最终交付

目前 ShadowCoach 已实现：

- Word、PDF 和文本简历输入；
- JD 匹配与能力诊断；
- 证据缺口识别与主动追问；
- 简历生成和局部多轮优化；
- 修改高亮、原因说明与版本管理；
- TXT、Word 和 PDF 导出；
- 登录、额度和支付宝支付；
- 多模型适配、超时重试与服务器部署。

## 3. Thoughts & Experiences：复盘体会

### Prompt 不能替代架构

当任务涉及判断、状态和结果验证时，继续增加 Prompt 规则无法解决根本问题。更有效的方式是拆分流程，并为每个阶段定义清晰的职责。

### Agent 的关键是边界

Agent 适合处理无法提前写死的判断，但事实来源、合法动作和停止条件需要由代码控制。

在简历这种强调真实性的场景中，可控性比自由度更重要。

### 追问也是产品能力

信息不足时，立即生成往往意味着猜测。与其输出一份流畅但失真的简历，不如先向用户提出一个准确的问题。

### Vibe Coding 不替代产品判断

AI 提高了页面开发、代码修改和问题排查的效率，但需求选择、质量标准和架构取舍仍然需要由人负责。

Vibe Coding 降低了实现成本，也让“应该做什么”比“能不能做出来”更加重要。

---

## 总结

ShadowCoach 从一个单 Prompt 的简历优化页面，逐步演进为一套能够诊断、追问、改写和校验的受控 Agent Loop。

这个项目最终验证了一个核心思路：

> 让模型负责理解与生成，让 Harness 负责上下文、状态、事实与执行边界。
